# A test result demotes the Upstream Key it is about

`testKey` on a non-disabled Upstream Key used to record the probe verdict on `lastProbe` and leave `health` alone for any verdict other than `usable`. That left an active key that just got rejected by the upstream marked `active`, and the Owner UI was forced to either show two contradictory signals (the badge and the inline verdict) or hide the contradiction behind a tooltip. The gateway kept routing to a key the upstream had just turned away, so the next request would 401 anyway. We made the test verdict the source of truth for the post-test health: `usable` activates, `rejected` demotes to `invalid_authentication`, and `inconclusive` demotes to `cooling_down` (with a 30-second back-off). A `disabled` key is still immune — a test informs, only the Owner's explicit Activate revives it. The same patch logic also drives the background trial loop so a single bad read during a trial has the same effect as a manual test. The Owner UI no longer needs a separate "Last test" line because the badge already carries the verdict; a discoverable info icon next to the badge exposes the upstream's specific reason (HTTP code, timeout, etc.) on hover.
