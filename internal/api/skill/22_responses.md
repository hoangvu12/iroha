## OpenAI Responses

`POST /providers/<handle>/v1/responses` serves Callers built on the Responses API (the OpenAI SDKs' `responses.create`, Codex with `base_url=<iroha>/providers/<handle>/v1`). Send the Gateway Key as `Authorization: Bearer`.

- **Passthrough** to an Endpoint speaking `openai-responses`: the body reaches the Provider byte for byte apart from the model (renames), so `store`, `previous_response_id`, tools, `text.format` and extensions keep working; headers such as `Idempotency-Key` are forwarded. Stream events pass through in order with their `event:` names; the `response` object in `response.created` / `response.completed` names the model you asked for.
- **Translation** to an Endpoint speaking Chat or Anthropic Messages, and from Chat or Anthropic Callers to a Responses Endpoint: instructions, input items (messages, images, `function_call` / `function_call_output`), function tools, `reasoning.effort`, reasoning summaries (from `reasoning_content` or Anthropic thinking), stop status and usage. A translated answer has the id `resp_<Request ID>`; a translated stream runs `response.created` ... `response.completed` with its own `sequence_number`s and the `content_part` events the SDKs' stream helpers need.
- **Stateful fields cannot be translated**: `previous_response_id`, `conversation`, `prompt` or `context_management` toward a Chat or Anthropic Endpoint gets `400 untranslatable_request` (send the whole history in `input` instead, as Codex does with `store: false`). A request translated *to* a Responses Endpoint is sent with `store: false` unless the Caller set it.
- Usage is recorded from `usage` (or `response.usage` in `response.completed`): `input_tokens` with `input_tokens_details.cached_tokens` and `.cache_write_tokens` (its `cache_write_tokens_details.ttl_12h_tokens` as `cache_write_long`), `output_tokens` with `output_tokens_details.reasoning_tokens`.

Errors use the OpenAI envelope. A stream is kept alive with `: keep-alive` comments; a failure after the stream began ends it with `event: error` (`{"type": "error", "code", "message", "param": null, "error": {...the envelope's error...}}`, which the OpenAI SDKs raise) and then `event: response.failed` (whose `response.error` Codex reports), never `response.completed`.
