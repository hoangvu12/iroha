# `/providers/{connection_id}/v1/messages` exposes an Anthropic-compatible public surface that translates both ways

Iroha exposes `POST /providers/{connection_id}/v1/messages` as an Anthropic-compatible public surface alongside the existing OpenAI-compatible `/v1/chat/completions` and `/v1/responses` routes. The route accepts Anthropic-shape bodies (`model`, `messages`, `max_tokens`, `system`, `tools`, `tool_choice`, `stream`, `metadata`, `service_tier`, `stop_sequences`, `temperature`, `thinking`, `cache_control`, `output_config`), streams Anthropic SSE events (`message_start`, `content_block_start`, `content_block_delta`, `content_block_stop`, `message_delta`, `message_stop`), and returns Anthropic-shape error envelopes (`{type: "error", error: {type, message}, request_id}`). When the Provider Connection points at Anthropic, the adapter passes the body through to the upstream URL and streams the response back. When the Provider Connection points at an OpenAI-shaped Provider, the adapter translates the Anthropic-shape request to OpenAI-shape using the inverse of the same round-trip, calls the upstream with OpenAI-shape, and translates the response back to Anthropic-shape — preserving SSE event timing and using OpenAI Chat Completions chunks on the wire to the upstream. The route is provider-scoped (matching ADR-0001); no unscoped `/v1/messages` exists. We rejected refusing `/v1/messages` against non-Anthropic Providers (makes the route useless for Owners with OpenAI-compatible Providers and contradicts the bidirectional-adapter decision in 0010), per-Provider opt-in (adds configuration surface for no benefit), and using the path-prefix passthrough pattern from Cloudflare (`/anthropic/v1/messages`) instead of the provider-scoped route (collides with ADR-0001). The v1 spec's prior "Anthropic-compatible public endpoints or automatic translation from Anthropic requests" exclusion is lifted at `.scratch/iroha-v1/spec.md:189` to make this work. LiteLLM (`litellm/proxy/anthropic_endpoints/endpoints.py:78-184`) and Bifrost (`core/providers/anthropic/anthropic.go` plus `responses.go`) both expose an Anthropic-shape surface with bidirectional translation against non-Anthropic Targets; Portkey and Cloudflare limit their Anthropic-shape surface to passthrough against Anthropic Targets only, and the bidirectional design is the more capable choice.
