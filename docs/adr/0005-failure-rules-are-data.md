# Failure Rules are data, editable at runtime

v1 encoded over a hundred provider quirks (Nous answering an empty account with 404, DashScope's two-meaning 403 codes, Z.ai quota codes that do not concern chat, Mistral's billing 402, and more) as TypeScript inside per-provider adapters, so every new quirk needed a code change and a deploy. In v2 each quirk is a Failure Rule: a match on status, error code or body text, scoped to a Provider or global, producing one outcome for the key, the model and the Request. Built-in rules ship with the binary and cover everything v1 handled; the Owner and agents add or override rules through the admin API, with a dry run against recent failed Attempts, and they take effect without a restart. Behaviour that must rewrite a response rather than classify a failure (moving a provider's `<think>` text into reasoning, flattening non-standard content blocks) stays in Go.
