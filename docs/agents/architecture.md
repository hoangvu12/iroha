# Architecture (read first)

One Go binary (`cmd/iroha`), one SQLite file (`<data-dir>/iroha.db`), pure-Go driver `modernc.org/sqlite` (no CGO, so `GOOS=linux go build ./cmd/iroha` works from Windows). Stdlib `net/http` only. Module path `github.com/hoangvu12/iroha`.

## The inference path

One Request runs through four seams, in this order. Change the seam that owns a behaviour; keep `internal/gateway` an orchestrator.

| Step | Owner | Today (04, 05, 09) | Who extends it |
|---|---|---|---|
| 1. Caller auth and scope | `gatewaykeys.Store.Authenticate`, `Caller.AllowsProvider/AllowsModel` | Gateway Key from Bearer, `x-api-key`, `api-key`; scope `all` or Providers each optionally narrowed to models. Unknown, disabled, archived and out-of-scope Providers get one 403 `provider_not_allowed`. | 12 (global routes, `/v1/models`), 15 (`x-goog-api-key`, `key=`), 18 (Pools in scope), 23 (Test caller) |
| 2. Candidate planning | `planner.Plan` over `providers.Store.Routing` | Endpoints in tiers (`endpointTiers`): the Endpoints of the Caller's Shape, then those of a Shape in `Request.Translate` (13); a later tier is used only when no earlier tier yields a candidate. Within a tier, keys go in the conversation's order (`Request.Affinity`, rendezvous hashing; prompt caching 02) or, with no conversation or affinity off, round-robin (`Counter` per Provider ID), each key on every Endpoint of the tier it may use (`Key.Allows`: restriction to Endpoints, 09); renames applied per Endpoint (`Endpoint.WireModel`). Disabled, invalid, cooling, model-cooling, Model Gap and restricted keys are skipped (`Result.Skipped`, the serving tier's only). Keyless keys (empty secret) are planned like any other. Empty plan says why (`no_endpoint`, `no_upstream_key`, `no_usable_key`, `keys_cooling` until T, or `model_gap` → 404 `model_unavailable`). Expired gaps in the routing view are deleted and logged first (`gateway/gaps.go`). | 10 (carriers first), 13 (append the other-Shape Endpoints as a second tier in `endpointTiers`: that alone gives "translate when no same-Shape Endpoint has a candidate"), 18 (Pool members) |
| 3. Attempt execution | `gateway/budget.go`, `gateway/attempt.go` | `exchange.serve` walks the candidates within the budget (`max_attempts`, default 3; first byte within 60 s of arrival, per Provider up to 95 s, one deadline per Request so a timed-out Attempt ends it). Each failure goes through `rules.Set.Classify`; invalid/cooling/model-gap outcomes go to `keystate.Store.Fail` (a gap leaves the Key State alone), and those keys are out for the rest of the Request (after a model cooling or gap, for that wire model only); when every Attempt was refused with `model_gap` the Caller gets 404 `model_unavailable`; a 5xx key+Endpoint is replayed once, last. `fail_request` answers the Caller; otherwise the error carries `details.attempts` and `summary`. One Attempt (`attempt`): `outbound` builds URL + op path, forwards Caller headers except credentials/hop-by-hop/`x-forwarded-*`/`cf-*`/`iroha-*`, applies static headers then the key per the Endpoint's auth style (`bearer`, `x-api-key`, `header` named by `auth_param`, `query` parameter named by `auth_param`, `none`); a keyless Attempt (`Key.Keyless`: empty secret or style `none`) sends no credential and drops any Caller header in the auth slot, and `noCredential` turns its `invalid` verdict into `retry_elsewhere`. Key tests (`keytest.go`) use the same `outbound`, with a tiny call per Shape (`testCall`) on the first Endpoint the key may use or `?endpoint=`. Redirects are never followed. Before relaying a 2xx answer, `embeddedError` (`embedded.go`) reads a stream up to its first data event (past comments) or a buffered body whole; if that is an error (`rules.EmbeddedError`), the Attempt fails with it (status 200, the event as `failure_body`) and is classified like any failure, else what was read is put back in front of the body. On a translated Attempt a whole 2xx answer that is not JSON (an HTML page) fails the same way (`notJSON`, read as a 502 by the rules); passthrough relays it as is. `relayStream` forwards SSE event by event with flush; `relayBuffered` otherwise. `passRelay` echoes the requested model, reads usage, drops the usage chunk Iroha injected (translated answers: see "Ticket 13: translation"). Streaming Requests (17, `stream.go`) run a keeper beside the budget loop: no upstream answer after `StreamCommitAfter` (10 s) commits 200 + stream headers, and `KeepAliveEvery` (15 s) of silence sends the Shape's keep-alive, before and during the stream. Every write to the Caller goes through `exchange.mu` (`writeHead`, `send`, `writeError`, `setHeader`); `x.fail` after commitment (or once a relayed stream began) writes the Shape's error event with the same envelope, the record keeping status 200 with the error code. A Shape that streams sets a `streamShape` (`keepAlive`, `errorEvent`) in its `shapeSpec`. | 07 (more built-in Failure Rules; agent rules from 06 arrive through `Options.Rules`), 13–16 (translate/normalise between relay and Caller; a `streamShape` per Caller Shape) |
| 4. Recording | `requests.Recorder`, log kinds `request` and `attempt` | Request inserted `in_progress` once the Caller is known (401s are not recorded), one row per Attempt, completed with status, error code, serving Provider/Endpoint/key/wire model, Shapes, first byte, duration, usage. Writes ignore the Caller's cancellation. With capture on, `exchange.begin` wraps `r.Body` and the response writer in a `requests.Capture` and `finish` stores it, so Attempt code never deals with capture: whatever reaches the Caller is captured. Failed Attempts store the matched `rule`, `outcome`, `reason`, `action`, `failure_headers` and `failure_body` (64 KiB); the Request gets a one-line `summary`. `NoteProvider` names the Provider as the first Attempt starts. Triggers (migration `25_01`) give every inserted or updated Request, and every stored capture, the next `rev`, so readers follow changes with `GET /api/requests?changed_after=<cursor>` and no writer has to know. | 13–15 (stream reassembly of other Shapes in `requests/capture.go`, `reassemblers`: Anthropic done in 13), 18 (write `requests.pool`, the Pool the Caller named; the feed already shows and filters it), 23 (Test Requests: `caller_kind = 'test'` (`requests.CallerTest`), name `Test` or `Test (as <key>)`, `gateway_key_id` may name the key: the `caller=<key ID>` filter never matches them) |

### Ticket 13: translation

- Routes: each provider-scoped inference route is `serveProvider(shape)`; the body is read by `readBody(r, shape)` into a `callerRequest` (Shape, model, stream, include_usage). Global routes: see "Ticket 12: global routes".
- Per Attempt, `exchange.prepare` picks passthrough (Endpoint Shape = Caller Shape: `preparePassthrough`, `passRelay`) or translation (`translate.New(...).Request`); the op path comes from `opFor(endpoint shape, wire model, stream)`. Translated answers go through `translatedBody` or `relayTranslatedStream`. Usage is always read from the upstream answer in the Endpoint's Shape (`usage.Reader`).
- Errors and keep-alives follow the Caller's Shape: `errorEnvelope(shape, ...)` and the `streamShape` of the Shape's `shapeSpec` (`gateway/shapes.go`; Anthropic: `ping` events, `event: error`).
- Adding a Shape (14, 15): a `codec` in `internal/translate` (DTOs, request fix-ups, upstream event reading, answer tidy-up, stream writer), golden cases, one `shapeSpec` in `gateway/shapes.go` (body hint, op path, error envelope, `streamShape`, passthrough echo, reported model, first-token test, key-test body), `usage.Reader` and `requests.reassemblers` entries, and its route via `serveProvider`.
- Normalisers (16) hook on the upstream answer in the Endpoint's Shape, before `passRelay` or `translate` sees it, so both paths get them.

Body edits are byte-preserving: `gateway/jsonedit.go` (`setField`, `field`, `echoModel`) replaces one top-level value in place, so passthrough never re-serialises a body. Streams of OpenAI Chat get `stream_options.include_usage` added when the Caller did not ask, so usage is recorded for every stream.

### Ticket 15: Gemini

- **Route**: `POST /providers/{handle}/v1beta/models/{model...}` (`gateway/gemini.go`). The model and stream flag come from the URL: `readBody` calls `readGeminiTarget`, which splits the method off at the last colon (`generateContent`, `streamGenerateContent`; anything else is 404 `operation_not_supported`) and keeps the rest, slashes included, as the model. Ticket 12's global Gemini route can reuse it as is and split `handle/model` itself.
- **Upstream op**: `opFor(shape, model, stream)` (was `opFor(shape)`); for Gemini it is `geminiOp`: `/models/<wire model>:generateContent`, or `:streamGenerateContent?alt=sse`. Iroha always asks Gemini Endpoints for SSE and always answers Gemini Callers with SSE (no JSON-array stream). On passthrough the body is untouched (no model field to rewrite) and `modelVersion` is echoed as the Caller's model.
- **Caller auth**: `gatewaykeys.Credential` also reads `x-goog-api-key` and the `key` query parameter. Upstream URLs are built from the Endpoint and the op only, so the Caller's query never reaches a Provider.
- **Errors and keep-alives**: Google's envelope (`geminiError`: `code` = HTTP status, `status` = gRPC name, Iroha's code as `reason`, plus `hint`, `request_id`). The keep-alive is a data chunk with one empty text part, because the Google SDKs parse every SSE line as JSON and choke on comments.
- **Codec**: `codec.chatHop` makes a Gemini Caller's answers go Endpoint → Chat → Gemini in two RelayKit steps (`translate/hop.go`), because RelayKit's direct converters drop reasoning and usage details; the writer patches thought parts and `usageMetadata` from the Chat form. `codec.noteRequest` reads `includeThoughts` from the request. URL images become `fileData` with a MIME type guessed from the extension.
- **Usage**: input = `promptTokenCount` + `toolUsePromptTokenCount`, output = `candidatesTokenCount` + `thoughtsTokenCount`, reasoning = thoughts, cache read = `cachedContentTokenCount`. Each stream chunk's counts are the running total.

### Ticket 14: OpenAI Responses

- Per-Shape files, following "Adding a Shape": `translate/responses.go` (codec), `gateway/responses.go` (`responsesStream`, `opResponses`, route docs, `echoResponsesEvent` for passthrough: the model lives in the event's `response` object), `usage/responses.go`, `requests/capture_responses.go`; one line each in `codecs`, `reassemblers`, `usage.Reader` and `Routes`, and its `shapeSpec` (`gateway/shapes.go`). The global `/v1/responses` waits for 12 (`serveScoped` with `shape.OpenAIResponses`).
- Two codec hooks were added for it, optional for other Shapes: `fixUp` (correct the decoded upstream DTO before conversion; Responses copies `output_tokens_details.reasoning_tokens` where RelayKit reads it) and `streamID` (name a stream converted to the Shape; Responses uses `resp_<Request ID>`, also for buffered answers). `Stream` passes `EmitSequenceNumber` (only Responses output uses it) and, before finalising, pushes the usage merged over every event into each converter step, so a two-step conversion (Anthropic → Chat → Responses) closes with the whole usage.
- The Responses stream writer renumbers `sequence_number`, adds the `content_part.added/done` events RelayKit leaves out (the SDKs' stream helpers need them), unwraps RelayKit's `{Type, Payload}` events and tidies every response object. Iroha's failure on a Responses stream is `event: error` (with a top-level `error` object, which the OpenAI SDKs raise) then `response.failed`.
- Responses stateful fields are refused by RelayKit toward Chat and Anthropic (→ 400 `untranslatable_request`); requests translated to Responses get `store: false` unless set; `store` is dropped toward Chat. The fake Responses upstream (`testkit`) now sends OpenAI's full event sequence for a message.

### Ticket 16: normalisers

- `exchange.prepare` takes `normalise.For(endpoint URL, endpoint Shape)` per Attempt and runs `RequestBody` on the body sent (passthrough or translated). The answer is normalised before anything reads it: a whole 2xx answer by `normaliseBody` (after `embeddedError`; a `normalise.Failure` makes it a failed Attempt with status 200), a stream event by event in `relayStream` (`normaliseEvent`, then `passRelay.data`) and `relayTranslatedStream` (before `translate.Stream.Event`). `Stream.End` runs only when the body ended without a transport error, and may add events (held text, a closing chunk, `[DONE]`).
- Selection: a normaliser for a model's quirk has no `Host` (relays pass it on); one for a service's own vocabulary has the service's hosts, like built-in Failure Rules. Each acts only when its construct is present and otherwise returns the same bytes, so passthrough stays byte-preserving. A rewritten JSON body is re-encoded (keys sorted, numbers kept, no HTML escaping).
- Adding one: an entry in `normalise.Builtin` and its code in the Shape's file (`chat.go`); a normaliser for another Shape needs `Set.Body`/`Stream` to dispatch on it, and `normaliseEvent` frames added events as data-only (enough for OpenAI Chat; a Shape with event names needs framing per Shape).

### Ticket 10: model lists

- **Configuration** lives on Providers and Endpoints (`internal/providers`): `strict` and `discovery` (`none`, `provider` default, `key`) on the Provider, `discovery_url` (`""` = `<url>/models`, `"none"`, or a URL) on the Endpoint. `providers.Routing` carries them (`Strict`, `Discovery`, `DiscoveryURLs`).
- **Before planning**, every inference route calls `models.Store.Prepare(ctx, &provider, model)` after the scope check: hidden models, and unlisted models of strict Providers (renamed Caller names count as listed), get 404 `model_not_found` before any Attempt; it then sets `planner.Key.Carries` from per-key lists, and `planTier` moves carriers of each Endpoint's wire model ahead of the other keys, keeping the key order (the conversation's, or round-robin) within both groups. Global routes (12) and Pools (18) call `Prepare` per Provider the same way.
- **Discovery** (`Store.Refresh(ctx, providerRef, dryRun)`, usable as a `jobs.Job` body for 20; `Store.LastRefreshOf` reads `model_refreshes` to find Providers that are due): per Endpoint (first usable key, up to 3 tried, keyless when the Provider has no key for it) or per key and Endpoint. Each successful list replaces its own rows in `provider_model_sources`; failed lists keep theirs. Lists of Endpoints set to `none`, of the other mode, and of keys restricted away are dropped; disabled or invalid keys' lists are kept unread. A key's list clears that key's Model Gaps for the models it names (`keystate.ClearGaps`, `track` nil). One `discovery` event per list plus one per refresh. `provider_models.reported` keeps each model's object as last discovered with metadata (a bare `{"id"}` keeps the earlier object; the first list in Endpoint and key order with facts wins), for metadata (11). ### Ticket 20: daily model refresh

- **When**: each Provider has a fixed time of day, `DailyAt(id)` (hash of the Provider ID, whole minutes UTC). It is due at the first occurrence of that time at least 12 h after its last refresh (`model_refreshes`, so a refresh by hand counts). Never refreshed, or due while Iroha was down: due at `max(start, created) + DailyAt mod 1h`, i.e. spread over the hour after the start (no burst) and a new Provider is discovered within the hour. Disabled, archived and `discovery none` Providers are not scheduled.
- **How**: the `model_refresh` job runs `jobs.Every(15m)` and refreshes what is due, one Provider at a time, so a refresh lands at most 15 min after its time. No table of its own: `model_refreshes` (10) is the state.
- **Tests**: a test that creates a Provider with keys and advances the clock past an hour now sees model-list GETs on its fake (`gateway` tests' `bearers` skips GETs). Tests counting `job.run` events filter on `attrs.job`.

### v1 import fix: secrets, auth style, static headers, repair

- **Secret rule**: a v1 key row with a non-empty decrypted secret is a secret key; only an empty secret makes a keyless slot (`keyless`, `keyless-2`, ...). `requires_upstream_key` is not read for this: v1 sent `<auth_prefix><secret>` in `auth_header` for every row that had a secret whatever the flag (the flag only allowed empty rows), and production had flag-0 Providers whose rows all held real keys.
- **Auth style**: every Endpoint gets the Provider's v1 auth style (`authStyle`), as v1 applied one header and prefix to all its base URLs. An Endpoint that only empty rows used stays keyless in effect: its keys are restricted to it and an empty secret sends nothing in any style.
- **Static headers** (`staticHeaders` in `plan.go`): decrypted v1 headers go on every Endpoint of the Provider and show in `GET /api/providers/{p}` (values as stored, like secrets: ADR-0006). One named like the auth header is left out with a note: v1 never sent it, and v2 refuses it (`checkEndpoint`), which would fail the Endpoint and all its keys. `Run` masks every v1 secret and header value in its output, also those the plan leaves out.
- **Re-run repair**: `PProvider.FormerSlots` lists the slot names the pre-fix import made for a flag-0 Provider (one per row, in row order) that no empty row maps to now. After the Provider's keys went in with no failure, `run.removeFormerSlots` deletes those of them v2 still holds with no secret, in one `keys/bulk/delete` (one revertible Audit Entry by the import's Admin Token); keys with other names or a secret are never touched. Report field `RemoveKeys`, summary `upstream_keys_remove=N`. Tests: `v1import/secrets_test.go`.

### Ticket 41: keyless Providers

- **Decision:** a keyless Provider is served by a real Upstream Key with an empty secret, never by a slot the planner invents. That keeps "every key has one Key State": cooling, Model Gaps, carriers, last use and the route preview attach to that key as they do to any other. To spare the Owner the extra step, creating or switching an Endpoint to auth style `none` on a Provider holding **no** Upstream Keys adds the key `keyless` in the same mutation (`providers.addKeylessKey`, called from the Endpoint create, bulk and PATCH routes; `EndpointResult.keyless_key`). It is tracked after the Endpoint, so one revert removes both. A Provider that already holds keys gets nothing (its keys send nothing to a `none` Endpoint anyway). The key is unrestricted, so on a Provider that later gains keyed Endpoints it also goes there, sends nothing, and a 401 there is `retry_elsewhere`; restrict or delete it if that wastes Attempts.
- **Empty static header** = not sent, and drops the Caller's header of that name (`gateway.setStatic`, the same in `models.discoveryRequest`).
- `KeyCounts.Keyless` (summary and overview) counts keys with no secret. The `no_upstream_key` hint names the keyless path.
- UI: Add Provider's "No key needed" switch (Endpoint `auth_style: none`), "Add keyless key" in the Keys tab's empty state and Add keys dialog (`calls.addKeylessKey`).
- Tests: `gateway/keyless_test.go`, `models/keyless_test.go`, `v1import/keyless_test.go` (the test chat, 23, included).

### Ticket 40: Endpoint Gaps

- **Decision (Owner, 2026-11-19):** an `invalid` outcome on one Endpoint, for a key that has worked on another Endpoint of its Provider, is an **Endpoint Gap** (key, Endpoint; no expiry) instead of the Key State `invalid`. It is a refinement of how `keystate.Store.Fail` applies `invalid`, not a rule: built-in and Owner rules alike (an Owner rule saying `invalid` is the Owner saying "the key is refused", and where it was refused is the same evidence either way; `gateway TestAnOwnerRuleSayingInvalidAlsoMakesAnEndpointGap`). `noCredential` runs first, so keyless 401s stay `retry_elsewhere`.
- **"Has worked"** is `key_endpoint_successes` (migration `40_01`): one row per key and Endpoint with the latest 2xx Attempt (`exchange.worked` → `keystate.Store.Worked`) or passing key test (`TestPassed`, which now takes the Endpoint). Attempt writes are throttled like `last_used_at`: the routing view carries `planner.Key.WorkedOn`, the Gateway skips the write when it is under `store.TouchEvery` old, and the upsert's `WHERE` throttles races. In `Fail`, only Endpoints the key may still use and has no gap on count (`workedElsewhere`), so a key refused everywhere it worked ends `invalid` after at most one refusal per Endpoint; going `invalid` clears its Endpoint Gaps (untracked, logged). A new secret deletes the key's rows (`keystate.Reset`).
- **Planning**: `planner.Key.EndpointGaps` (Endpoint IDs); `skip` reports `SkipEndpointGap` with `Skip.Endpoint`, after disabled/invalid/cooling; an all-gapped plan is `no_usable_key` with a message naming the gap. Budget loop: an Endpoint Gap effect (`keystate.Effect.EndpointGap`) puts the key+Endpoint pair out, like `retry_elsewhere` without a replay. The Attempt keeps outcome `invalid`; its `action` says "Endpoint Gap on <endpoint>" (the UI's `attempt-info.ts` reads that). Test chat pins ignore gaps and forget `WorkedOn`, so a pinned success clears the gap it disproves. Key tests without `?endpoint=` pick the first allowed Endpoint with no gap.
- **Clearing**: passing key test or 2xx Attempt on that Endpoint; `updateKey` when the secret or restriction changes (`clearEndpointGaps`, tracked as `keystate.EndpointGapResource`, so the edit's revert restores them; renames and enable/disable do not clear); `POST .../keys/{key}/clear-endpoint-gaps` (`?endpoint=`) and bulk. `POST .../keys/{key}/restrict-to-working-endpoints` (and bulk) = `updateKey` with the allowed Endpoints minus the gapped ones (`restrictToWorking`), so the key is tracked first and its gaps after: one revert restores both; `unchanged` without gaps, 409 `no_working_endpoint` when nothing would be left (only reachable after an Endpoint is deleted).
- **API**: `UpstreamKey.endpoint_gaps`, `.worked_on`; `GET /api/providers/{p}/endpoint-gaps`; summary `endpoint_gaps`; route preview skip `endpoint_gap` with `endpoint`. Log kind `endpoint_gap` (`keystate.KindEndpointGap`). Skill: `25_key_states_endpoint_gaps.md`. Tests: `gateway/endpointgaps_test.go`, `planner TestAnEndpointGapSkipsTheKeyOnThatEndpointOnly`.
- **UI**: Keys table shows an "Endpoint Gap" pill (and a `gaps` filter count), the key's sheet lists gaps with Clear and one "Restrict to working Endpoints" action (it was the key dialog; see "UI ticket 27"), the Pool Route tab and Requests' Route view name the skip and the jump.

### Ticket 31: Idempotency-Key and the replay pause

- **Idempotency-Key**: `newExchange` mints a UUID (`ids.UUID`) when the Caller sent no `Idempotency-Key`; `attempt` sets it on every outbound Attempt (a Caller's value is forwarded like any header). Key tests send none.
- **Replay pause**: a 5xx replay is queued with `notBefore` = failure time + `replayPause` (250 ms x 2^(n-1) up to 8 s, jitter x0.5-1.5; a longer `Retry-After`/`Retry-After-Ms` wins up to 60 s). Before the replay `serve` sleeps on the injected clock until then (`pauseUntil`; the Caller leaving ends it as `caller_gone`). A replay whose `notBefore` is not before the first-byte deadline is skipped.
- **Tests that replay a 5xx** now wait on the fake clock. If the test is not about the pause, call `srv.SkipShortWaits(time.Second)` first (testkit moves the clock to any timer due within that window; keep it below waits the test drives, such as the 10 s stream commit). Tests about the pause use `srv.Clock.BlockUntilDue` and `Advance` (`gateway TestAReplayOnTheSameKeyWaitsFirst`). `clock.Fake.Next` reports the earliest pending timer.

### Ticket 30: structured output and search results

- **Structured output** (`translate/format.go`): two codec hooks. `readFormat` (Caller side) reads the Caller's JSON schema or JSON mode from the decoded request into a Shape-neutral `outputFormat` (the schema kept as raw bytes); `writeFormat` (Endpoint side) writes it into the converted request before `prepareRequest`. Chat, Responses and Anthropic Endpoints always get Iroha's version, replacing RelayKit's where it had one, so the schema's properties keep the Caller's order (`toMap` would sort them; a `json.RawMessage` or an ordered `object` inside the map is written as is). A Gemini Endpoint keeps RelayKit's `responseSchema` when it wrote one, else gets `responseJsonSchema`. Toward Anthropic, `anthropicSchema` fits the schema to Anthropic's subset as its SDKs do (unsupported keywords into the description, `additionalProperties: false`, `oneOf` → `anyOf`) with a `schema_keyword_moved` diagnostic; JSON mode is dropped with `unsupported_response_format`. A schema with no name gets `response` toward OpenAI.
- **Raw rewrite** (`codec.rewrite`): fixes the Caller's body before it is decoded into RelayKit's DTO. Anthropic uses it to turn `search_result` blocks into text (`searchResultsAsText`); only `messages` is re-encoded.

### Review fixes: late non-stream answers (story 19)

- **Padding** (`gateway/pad.go`): for a non-stream Request, `attempt` calls `answerBegan` when a 2xx answer's headers arrive (after `disarm`) and `answerEnded` when that Attempt ends. While an answer is being read, the padder commits at max(arrival + `AnswerCommitAfter` (10 s), headers + `AnswerGrace` (5 s)), capped at arrival + 95 s: `200` + `application/json`, no body, `exchange.padded`. Then a newline every `KeepAliveEvery` of silence. `writeHead` lets the body follow the padding; `writeError` writes the Shape's JSON envelope as the body (status stays 200, the record keeps the error code). Nothing is committed while waiting for an answer to begin, so pre-answer failures keep their status. `relayBuffered` now writes through `x.send` and `x.end`, since the padder may write beside it.
- Decided over a total deadline (fails long generations that would otherwise finish) and over committing on arrival (turns 429/5xx into 200s). Skill: `20_gateway_late_answers.md`; conformance: TIME-02.

### Review fixes: time to first token (story 75)

- `first_byte_ms` is the time to first token: `relayResult.sawEvent` notes each upstream event, and `tokenEvent(endpoint Shape, payload)` (`gateway/firsttoken.go`) says whether it carries content (Chat delta content, reasoning, refusal or tool calls; Anthropic `content_block_delta` or a tool-use block start; Responses `response.*.delta`; Gemini a non-empty text or function-call part). `ttft()` falls back to the first event. The first-byte budget (`deadlineContext`, `disarm`) is unchanged.

Nested admin resources (Endpoints and Upstream Keys under a Provider) resolve their parent with the Provider resource and themselves by name or ID *within* that Provider (`resolveChild` in `internal/providers`); their audit names are `<handle>/<name>`, so `GET /api/audit-entries?record=acme/key-1` works.

## Rules everyone follows

- **Time**: never call `time.Now`, `time.After`, `time.NewTimer` or `context.WithTimeout` for anything behaviour depends on. Take a `clock.Clock` and use `c.Now()`, `c.NewTimer`, `clock.WithTimeout(ctx, c, d)`, `clock.Sleep`. Tests use `*clock.Fake`.
- **Stored times** are `INTEGER` unix milliseconds UTC named `*_at`; convert with `store.Millis` / `store.FromMillis` / `store.NullMillis`.
- **Writes** go through `db.Tx(ctx, func(tx *sql.Tx) error {...})` (takes the write lock up front).
- **JSON** fields are `snake_case`; times RFC 3339.
- **Errors** returned from handlers are `*api.Error` with a code, message and a hint naming the next action (`api.Errorf`, `api.BadRequest`, `api.NotFound`). Anything else becomes a 500 and is logged as `http.error`.
- **Secrets** (Admin Tokens, Gateway Keys, Upstream Keys) are stored readable (ADR-0006) but never written to logs.
- Modules take their dependencies explicitly (`*store.DB`, `*slog.Logger`, `clock.Clock`, `*http.Client`); no globals, no service locator.

## Add an admin resource

Every configuration record the API changes (Provider, Endpoint, Upstream Key, Model Pool, Gateway Key, Failure Rule, setting) goes through `internal/audit`, so it gets name-or-ID addressing, `dry_run`, bulk, create-or-update, Audit Entries and revert without new machinery. `internal/admintokens/routes.go` is the worked example; copy its shape.

1. **Snapshot type.** A struct of the record's *configuration* fields as JSON (`snapshot` in admintokens). Leave runtime state out (last used, Key State, counters, discovered lists): it changes without Audit Entries and would make every revert a conflict. When you later add a field, give it a zero value that means the old behaviour; old entries are compared only on the fields they have.
2. **Register the resource** at package level:

   ```go
   var Resource = audit.Register(&audit.Resource[snapshot]{
       Name: "provider", Label: "Provider", Plural: "Providers", Path: "/api/providers",
       Table: "providers", NameColumn: "handle", Secrets: nil,   // Secrets: snapshot fields masked in Audit Entry views
       NameOf:  func(s snapshot) string { return s.Handle },
       Load:    func(ctx, q audit.Querier, id string) (*snapshot, error) { /* nil, nil when absent */ },
       Restore: func(ctx, tx *sql.Tx, id string, s *snapshot) error { /* nil: delete; else upsert */ },
   })
   ```

   `Restore` must update in place (`INSERT ... ON CONFLICT (id) DO UPDATE`), never delete and re-insert, or foreign-key cascades take children with it. Return an `*api.Error` (409) when the current state forbids the restore (name now taken, children present).
3. **Read routes** address records with `Resource.Resolve(ctx, db, c.Path("provider"))` (ID or name; uniform 404 with a hint) or `Resource.Get`.
4. **Mutating routes** put `audit.DryRun` in `Query` (`TestDocumentsDescribeTheConventionsOnce` fails otherwise) and run their writes inside the Trail:

   ```go
   var out Provider
   res, err := tr.Mutate(c, "provider.update", "Edited", func(m *audit.Mutation) error {
       id, err := Resource.Resolve(m.Ctx, m.Tx, c.Path("provider"))
       if err != nil { return err }
       if err := m.Track(Resource, id); err != nil { return err } // before every write, also before an insert of a new ID
       // ... writes on m.Tx, using m.Now for times ...
       out, err = read(m.Ctx, m.Tx, id)
       return err
   })
   return ProviderResult{Result: res, Provider: out}, err   // type ProviderResult struct { audit.Result; Provider Provider `json:"provider"` }
   ```

   `Mutate` handles `dry_run` (runs everything, rolls back), computes `changes` and `outcome` from the first tracked record, writes one Audit Entry when anything changed, logs `config.change`, and answers 201 when the record was created. `Track` every record the change touches, children included (deleting a Provider tracks its Endpoints and keys), parents before children: revert re-creates in tracking order and deletes in reverse. Call `m.Irreversible(reason)` for changes that must not be undone (revoking a secret); `m.Summarize(text)` replaces the generated summary ("Edited Provider acme", "Disabled 3 Upstream Keys").
5. **Create-or-update by name**: `POST /api/<resource>` looks the name up in `m.Tx`; if found, apply only the fields sent (pointer fields in the body) to that record, else insert. The second identical call is then `unchanged` with no Audit Entry.
6. **Bulk**: `POST /api/<resource>/bulk` (create-or-update many) and `POST /api/<resource>/bulk/<action>`, body `audit.BulkRequest[T]`, response `audit.BulkResult[Out]`, implemented by reusing the single-item function: `return audit.Bulk(tr, c, "upstream_key.disable", "Disabled", in.Items, h.disable)`. Each item runs in a savepoint; an `*api.Error` rolls back that item only; any other error aborts the call. One Audit Entry covers the applied items.
7. **Errors**: return `*api.Error` with a code and a hint (`api.BadRequest`, `api.NotFound`, `api.Conflict(code, hint, ...)`, `api.CheckName` for names). Add a new code to the list in `internal/api/skill/10_conventions.md` only if agents should branch on it.

Do not describe these conventions again in your routes' text; `internal/api/skill/10_conventions.md` and the OpenAPI `info.description` say them once. Tests: drive the routes through `testkit` (`srv.NewAdminToken(name)` gives a second actor); assert outcomes, `changes`, `GET /api/audit-entries?record=...`, and that `POST /api/audit-entries/{id}/revert` restores the before-state.

## Add a background job

Iroha runs only the jobs the spec names (hourly retention, daily model refresh). A job is a name, a schedule and a function; add it in `server.New` next to `retention.Job`:

```go
jobs.Job{Name: "model_refresh", Description: "...", Schedule: jobs.Every(15 * time.Minute),
    Run: func(ctx context.Context, dryRun bool) (jobs.Outcome, error) {
        // do what is due; with dryRun, report what would be done and change nothing
        return jobs.Outcome{Summary: "Refreshed 2 Providers.", Details: map[string]any{"refreshed": 2}}, nil
    }}
```

`jobs.Every(d)` first runs `d` after the first start (no burst at startup), then keeps its rhythm across restarts (next = last stored start + `d`, at once when overdue). Write your own `Schedule` (`Next(last, now)`) for anything else; for per-Provider times spread across the day, run often and act on what is due, keeping per-Provider results in your own table. The runner passes `ctx` (cancelled at shutdown: outcome `canceled`), recovers panics (outcome `failed`), never overlaps runs of one job, stores each run (latest 100 per job; dry runs are not stored) and logs `job.run` with your `Details` as attributes (set `Outcome.Provider` to link the event to a Provider). `GET /api/jobs` shows schedule, next run and last run; `POST /api/jobs/{job}/run` runs one now. In tests, add jobs with `testkit.Options{Jobs: ...}`, advance the clock, then `srv.SettleJobs()` waits for the runs that time triggered; `srv.RunJob(name)` runs one through the API.

### UI motion system

Shared by motion tickets 13–20 (spec story 15), set by an `improve-animations` audit (Owner, 2026-11-19). Tokens live in `styles/index.css` ("Motion tokens", and the reduced-motion rule at the end of the file); `styles/motion.test.ts` pins them. Use the tokens, never a typed number (`duration-150`, `ease-[cubic-bezier(...)]`, `scale-95`). If a value is missing, add a token here and in the test; don't add a one-off. The app is a crisp dashboard: no bounce, no springs on things nobody drags, nothing over 300 ms except sheets (300) and toasts (400).

**Curves** (Tailwind `@theme`; also `var(--ease-*)` in CSS). The utility `ease-out` is the strong curve, not Tailwind's default; `ease-in` does not exist.

| Utility | Curve | For |
|---|---|---|
| `ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | anything entering or leaving; indicators; presses |
| `ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | something moving from one place on screen to another without a press (reorder settling, canvas pan to a card, zoom buttons) |
| `ease-drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | sheets and the chat panel |
| `ease` (CSS keyword, Tailwind `ease-[ease]`) | | hover colours, toasts |

**Durations** (`--duration-*` in `:root`, utilities `duration-<name>`):

| Token | ms | For |
|---|---|---|
| `hover` | 150 | colour/background on hover and selection (Tailwind's `transition-colors` default is also 150) |
| `press` | 160 | `:active` scale |
| `release` | 100 | the scale back when let go (the response snaps) |
| `tooltip` | 125 | tooltip in and out |
| `popup-in` / `popup-out` | 180 / 120 | menu, select, combobox, autocomplete, popover |
| `dialog-in` / `dialog-out` | 200 / 150 | dialog, alert dialog and their backdrop |
| `sheet-in` / `sheet-out` | 300 / 240 | sheet stack, chat panel, older sheets moving aside or back, the stack's backdrop (UI ticket 27) |
| `indicator` | 200 | tab and segmented indicator |
| `collapse` | 200 | disclosure, expandable row (height), its chevron's rotation |
| `move` | 250 | on-screen repositioning |
| `list-in` / `list-out` | 200 / 150 | a row, bulk-action bar or pill appearing / leaving |
| `toast` | 400 | toast enter, stack, leave |
| `fade` | 150 | a plain crossfade; a sheet's opacity |
| `flash` | 1600 | background of a just-arrived row fading back (WAAPI: read it with `getComputedStyle(document.documentElement).getPropertyValue("--duration-flash")`) |
| `scrollbar-in` / `scrollbar-out` | 100 / 200 | a Scroll Area's bar showing on hover or scroll / fading once idle (it lingers, unlike other exits) |

**Distances and scales** (`--motion-*`, used as `scale-(--motion-scale-popup)`, `translate-y-(--motion-shift)`): `scale-popup` 0.96 (popups and dialogs start and end here, never `scale-0`), `scale-press` 0.97, `shift` 8px (bar, pill), `shift-sm` 4px (row), `sheet-offset` 100% (a sheet's own width), `toast-offset` 100% (a toast's own height).

**Recipes** (UI SDK state attributes, never mount timers or `useEffect` flags):

- **Popup from a trigger** (menu, select, popover, combobox, tooltip): `origin-(--transform-origin) transition-[opacity,scale] duration-popup-in ease-out data-starting-style:scale-(--motion-scale-popup) data-starting-style:opacity-0 data-ending-style:scale-(--motion-scale-popup) data-ending-style:opacity-0 data-ending-style:duration-popup-out`. Tooltip: `duration-tooltip` and `data-instant:duration-0` (the next tooltip after one was open shows at once). `ui/popup.ts` `popupClass` is the one place menus and selects get this; reuse it.
- **Dialog**: same, but centred (no `--transform-origin`), `duration-dialog-in` / `data-ending-style:duration-dialog-out`; backdrop `transition-opacity` with the same durations.
- **Sheet** (stack, chat panel): enter and leave along the same edge. `data-starting-style:translate-x-(--motion-sheet-offset) data-ending-style:translate-x-(--motion-sheet-offset) data-starting-style:opacity-0 data-ending-style:opacity-0 [transition:translate_var(--duration-sheet-in)_var(--ease-drawer),opacity_var(--duration-fade)_var(--ease-out)] data-ending-style:[transition-duration:var(--duration-sheet-out),var(--duration-fade)]`. Older sheets move aside with the same translate transition on the same frame (no stagger). Opacity gets its own duration so it can still fade when reduced motion zeroes the slide.
- **Indicator** (Tabs `TabsIndicator`, `SegmentedControlIndicator`): position with `translate-x-(--active-tab-left)` / `translate-x-(--segmented-control-indicator-left)`, never `left`; `transition-[translate,width] duration-indicator ease-out data-[activation-direction=none]:transition-none` (no slide on first placement). Panels swap at once.
- **Press**: the `press` utility (`styles/index.css`, see "UI ticket 13") on Buttons and icon buttons: scale to `--motion-scale-press` on `duration-press ease-out` while held by a pointer, back on `duration-release`, hover colours on `duration-hover ease`; not on rows, menu items, tabs or checkboxes.
- **Collapse** (Collapsible, expandable rows): `h-(--collapsible-panel-height) overflow-hidden transition-[height] duration-collapse ease-out data-starting-style:h-0 data-ending-style:h-0`; chevron `transition-[rotate] duration-collapse ease-out`.
- **Row, bar or pill that isn't a UI SDK popup**: `animateIn(el)` / `animateOut(el)` from `@ui-sdk/core` set `data-starting-style` / `data-ending-style` on a plain element and wait for the exit, or CSS `@starting-style`. Enter `translate-y-(--motion-shift)` (rows: `--motion-shift-sm`) + `opacity-0` → place, `duration-list-in ease-out`; leave opacity only, `duration-list-out`. Table rows never animate height: siblings close the gap at once.
- **Toast**: `transition-[translate,opacity,height] duration-toast ease-[ease]`, start `translate-y-(--motion-toast-offset) opacity-0`; `data-swiping:transition-none` (the finger drives it).
- Hover: Tailwind's `hover:` already applies only on devices that hover, so touch never sticks. Never `transition-all`. `will-change` only after a trace shows a 1 px shift.

**Reduced motion** (one `@media (prefers-reduced-motion: reduce)` rule on `:root`): what moves or changes size holds still, because `press`, `release`, `indicator`, `collapse`, `move`, `sheet-in` and `sheet-out` become `0ms`, distances `0`, scales `1`, and `animate-pulse`/`ping`/`bounce` become `none` (Skullet stops its shimmer itself). What may fade: enter/exit of popups, dialogs, sheets, rows and toasts, hover colours and the arrival flash keep their durations, and with no distance or scale left they play as plain fades. Built from the tokens, a component needs nothing more. `motion-reduce:transition-none` on existing parts is fine (stricter). JS-driven motion (WAAPI, scroll) checks `matchMedia("(prefers-reduced-motion: reduce)")` itself and keeps opacity and colour only.

**Never animate**:
- **Keyboard actions.** The page shortcuts P/G/R (no page transitions at all), C toggling the chat panel (open it instantly when the key did it; slide only for a pointer), arrow/Home/End moving a highlight in menus, lists and tables, the canvas's `+ − 0` and Tab-to-card pan, Escape (popups use their normal short exit, nothing extra), `Kbd` hints.
- **High-frequency or 1:1 surfaces.** Row hover (instant background), selection checkboxes (colour only), sorting, filtering, search results, page changes (keep the previous rows, no skeleton), drag/wheel/pinch on the canvas, a drag in progress, scrolling (no smooth scroll; chat sticks to its end instantly).
- **Data that refreshes on its own.** Polled numbers, counts, Key States, the route preview every 5 s, streamed tokens in a reply: they change in place. The only arrival motion is a new Requests feed row (shift-sm + flash), all rows of one poll together, no stagger.
- Theme switching (the `.dark` class flips colours at once; suppress `transition-colors` for that frame).

```tsx
  col.accessor((k) => k.state.state, { id: "state", header: "State", filterFn: (row, _id, v) => row.original.state.state === v }),
]);
```

- **Sorting:** every accessor column sorts unless `enableSorting: false`; display columns don't.
  - `sortFn` is a comparator on rows (`a.original`). It can also be a built-in name: `"alphanumeric"`, `"basic"`, `"datetime"` or `"text"`.
  - Break ties inside it, by name. The first press sorts ascending, and there is no "unsorted" third press.
  - The header string names the button "Sort by <header>". Give `meta.label` when the header isn't text.
- **`filterFn`** matches this column's entry in `columnFilters`. It is either `(row, id, value) => boolean` or one of `"includesString"`, `"equals"`, `"arrIncludesSome"`.
- **`meta`** (`DataColumnMeta`):
  - `width`: a class on the header cell.
  - `align: "right"`: numbers, with tabular figures.
  - `className`: classes on the body cells.
  - `label`: the column's name when the header isn't text.
  - `opens`: the cell becomes a button "Open <name>" that calls `onRowClick`, the keyboard's and agents' way to open the row. Put it on the name column of a clickable table, and only around plain text. A cell that is already a `RecordLink` (ticket 10) needs no `opens`: the link is the way in.
- **One fact per cell.** A cell may hold a `RecordLink`, a `StatusDot` word or a pill.

**Props.** Every table needs:
- `id`: a stable name. It keys the remembered page size and the skeleton's shape.
- `label`: names the table, its scroller and "Loading <label>".
- `columns`, plus `data={query.data}` (`undefined` means loading).
- `sample`: from `pages/<page>/samples.ts`.
- `getRowId`: the record's ID, never the index, since selection and expansion key off it.
- `rowName`: the name every row control carries.

The rest are optional.

- **States in place of the table:**
  - `error` and `onRetry`: `ErrorState`, while there is no data.
  - `empty`: `EmptyState` with its one action, when there are no rows and nothing filters. The toolbar hides then.
  - `filterChips`, `onClearFilters` and `noResultsTitle`: `NoResults` with chips. Write the title in the table's own words, with Glossary capitals ("No keys match", "No Requests match").
  - `noResults` replaces the whole `NoResults`.
- **Toolbar, search, filters:** the page owns the controls and their state, in the URL as Keys does (`?q=`, `?state=`). It passes:
  - `toolbar`: the search box and filters.
  - `search`, with `searchFn(row, needle)`. The needle arrives lower-cased and trimmed. By default, any text column containing it matches.
  - `columnFilters`: `[{ id: "state", value: "cooling" }]`.

  A new search, filter or sort goes back to page 1. A page left empty shows the last page.

  A Select in a toolbar is `w-full`, and `cn` has no tailwind-merge, so a width class on it loses. Wrap it in a sized box instead: `<div className="w-28 shrink-0"><Select …/></div>`.
- **Sorting:** `defaultSorting` lets the table keep the state. `sorting` + `onSortingChange` keep it in the URL: Keys maps `?sort=&dir=` to and from `[{ id, desc }]`. Add `manualSorting` when the server sorts.
- **Selection and the bulk bar:** `bulk={(sel) => <>…buttons…</>}` turns selection on. That adds:
  - A checkbox column, with Shift-click for a range; the whole cell is the box's hit area.
  - Select mode while anything is selected: a row click toggles the row instead of opening it (see "UI ticket 25").
  - The header box "Select all rows on this page", which shows mixed when some are selected.
  - A bar that replaces the toolbar while anything is selected. It is `role="group"` "N selected", and shows your buttons, "Select all N" when the whole page is selected and more rows match, and "Clear selection".

  `sel.ids` holds the selected row IDs on every page, `sel.rows` the selected rows that are loaded, and `sel.clear()` clears it. Show the bar's results in the bar (`useSave` with `SaveStatus`/`SaveError`, ticket 04). Selected rows that leave `data` are dropped. Use `selection` / `onSelectionChange` only if the page must own the selection.
- **Row actions:** use `rowActions={(r) => <RowMenu name={r.name}>…MenuItems…</RowMenu>}`. It is the last cell, a ⋯ named "More for <name>"; pass `copy={useCopy().state}` for a copy made from the menu (ticket 04).
  - A `Switch` may sit beside the menu.
  - "Test in Chat" items call `useChatActions().open(target)` (ticket 22).
  - Destructive items are `MenuItem danger` and call `confirm.ask`. Use one `useConfirm()` per table, with `{confirm.dialog}` rendered once beside the `DataTable`.
  - The bulk "Delete…" names the count in the title and the first five names in the body. See Keys `askDelete`, and ticket 21.
- **Clickable rows:** `onRowClick(row)` opens the record: Keys sets `?key=`; others open a sheet, `useSheets().open(rec.provider(h))` (ticket 10). Clicks on the row's own controls don't open it, so cells need no `stopPropagation`. That covers buttons, links, inputs, checkboxes, switches, menu items, and anything inside a popup or dialog rendered in place.
- **`rowTone={(r) => … ? "danger" : undefined}`** tints a row red.
- **Expandable rows** (Audit Entries): `renderExpanded={(r) => <Diff …/>}` adds a chevron column, "Show details of <name>" / "Hide details of <name>" with `aria-expanded`. The details sit in a full-width row underneath. The chevron rotates; the row doesn't animate its height (motion system).
- **`columnVisibility={{ key: false }}`** hides columns (the Requests `?hide=`).
- **Phones (< 768 px):** `phoneRow={(r) => <two lines/>}` turns the table into a `ul` named `label`, with one two-line row per record (C31).
  - With `onRowClick`, each row is a button "Open <name>", and its menu lives in the record it opens. Without it, `rowActions` sits at the end of the row.
  - With `bulk`, the toolbar gets Select / Done, which shows the checkboxes; a tap then toggles the row.
  - Without `phoneRow`, phones get the table, scrolling sideways.
- **`footer={({ shown, total, from, to }) => …}`** is the line left of the pager ("42 keys", "12 of 42 keys").
- **Loading:**
  - The skeleton is built in: `id` `table:<id>` (`table:<id>:phone` on phones), label "Loading <label>".
  - When the page, sort or filter changes the query key, use `placeholderData: keepPreviousData` and pass `dimmed={query.isPlaceholderData}`. The old rows stay, dimmed, with no skeleton.
- **Scrolling:** the page scrolls the rows; the table is as tall as its rows and its header stays at the top of the window (see "UI ticket 25"). There is no `maxHeight` any more.

**Paging** (`paging`, spec "Pagination"):
- **`{ mode: "pages" }`** (the default): numbered pages over the loaded rows.
  - Pages hold 25, 50 or 100 rows (`PAGE_SIZES`; `sizes` overrides).

- **`{ mode: "server", pagination, onPaginationChange, rowCount }`**: Models in 07, Requests' numbered pages in 09.

  - Pass the page's rows as `data` and all matching rows as `rowCount`.

### UI ticket 16: table motion

Built into `DataTable` and the shared controls, so a page needs nothing:
- **Rows added or removed after an action** (`ui/row-motion.ts`, `useRowMotion`).
  - Only when `data` changes and still shares a row with the last `data`, in `pages` and `none` paging, and not while `dimmed`.
  - A new row enters with `animateIn`: shift-sm + fade, `duration-list-in`.
  - A row gone from `data` is drawn again in its old place for its exit: its last element, `inert`, `aria-hidden`, `data-leaving`. It fades (`animateOut`, `duration-list-out`), then leaves, and the rows under it close the gap at once.

  - In jsdom a leaving row is gone at once (no animations). Tests that hold it there stub `getAnimations` as `ui/table-motion.test.tsx` does.
- **Bulk bar** (`BarSlot` in `DataTable.tsx`, over `ui/presence.ts` `useLeaving`).
  - It rises in (`--motion-shift`, `duration-list-in`).
  - When the selection clears, it fades out in place (`duration-list-out`, inert, still showing the last selection). The toolbar fades back in under it in the same grid cell (`animateIn`, `duration-fade`): one crossfade.
  - Selecting again mid-exit turns it back. Its own component, so the exit ending doesn't re-render the table.
  - `useLeaving(value)` is the reusable form for any plain element that should fade out with what it last showed. `SaveStatus` uses it: a result whose time is up fades out, while "Saving…" replaces one at once.
- **Dimmed rows** (`keepPreviousData`) dim only after `--duration-fade`, so a fast answer never flickers, and come back at once.
- **Expanded details** fade in (`starting:opacity-0`, `duration-fade`) and close at once.
- **Controls**:
  - The `Segmented` indicator moves by `translate` (never `left`) on `duration-indicator`, with no slide into its first place.
  - The `Switch` thumb moves on `duration-press`, so it jumps under reduced motion.
  - Checkbox, segmented item and switch track colours use `duration-hover ease-[ease]`.

- **`row-reveal`** (`styles/index.css`) is for a row's quiet buttons (copy a secret, Test in Chat).
  - Hidden until the row (the `group`) is hovered, where there is hover.

- **Still**: row hover and press, selection colour aside; sorting; filters; search; page changes; the sort arrow; `activeRowId` scrolling.

### UI ticket 26: skeleton to data with a lot of data

The switch from a skeleton to a big table was one long task (1-2 s at 4x CPU for 60-100 rows). What it cost and why is in `iroha-v2-notes/v2-ui/skullet.md` ("Performance"); in short, Skullet 0.0.3 forces a layout per piece and per image while it reveals, and copies the content to remember its shape. Built so pages need nothing:
- **Reveal rule** (`app/skeletons.tsx`): the provider's reveal is `SKELETON_REVEAL`, Skullet's `smart` except that content of more than `SEQUENCE_PIECES` (60) pieces crossfades whole (`together`, two opacity animations) instead of coming in piece by piece. `revealFor(context)` is the rule. - **Rows after the reveal** (`ui/reveal-rows.ts`, `useRevealRows`): when more than `REVEAL_ROWS` (30) rows replace DataTable's skeleton, the reveal renders the first 30 (more than a window) and the rest follow in a transition on the next frame. Counts, selection and paging use every row from the start. Rows present from the start, refetches and later changes render whole. Tests that load many rows through a skeleton wait for the rest (`waitFor`).
- **Big skeletons** (`styles/index.css`, after `.skeleton-hold`): a skeleton drawn from a big table's remembered shape (Skullet keeps the last shape of `table:<id>` in memory, e.g. the feed's 100 rows: 1,414 bones, 1.6 s to draw at 1x) is cut at a window's height (the table's scroller, or a phone list, clips at `100vh` inside `[skullet-loading]`; Skullet draws no bone outside a clipping element), its rows past the 30th are `display: none`, and a skeleton of more than 20 rows pulses (`--skullet-animation: pulse`, opacity, composited) instead of sweeping. - **Logos** (`ui/LogoTile.tsx`): the image gets its `src` in an effect, so no image is loading when Skullet reveals (it gives each one a shimmering block of its own, with a forced layout each).
- **Skeleton content is inert** (`ui/Skeleton.tsx`): whatever renders for a skeleton (the sample, or the rows last shown when the same `Skeleton` loads again) sits in a `display: contents`, `inert` box that stops clicks, presses and keys in the capture phase, so even a dispatched event (a script, an automation) never reaches a sample row's handlers. `useIsSample()` is true for both.

- **No copy of the gateway's reading**: an Attempt's failure reading is two functions in `gateway/embedded.go`, `failureBody` (non-2xx) and `answerFailure` (a 2xx that is an error inside, a normaliser's failure, or non-JSON on a translated path), called by `attempt` and by the route on an `http.Response` built from the typed answer; then the live `rules.Set.Classify` and `noCredential` (keyless key or auth style `none`). A typed body without Content-Type is read as an event stream when it starts with `data:`/`event:`/`:`, as JSON on `{`/`[`; a pasted stream counts as the answer to a streamed request; the route reads passthrough unless `translated` is sent (then a non-JSON 2xx page fails, read as a 502). `answerFailure` also says whether the failure was an error inside the answer, which is all `embedded` means (a normaliser's finding or a non-JSON page is not). The first cooling is `keystate.FirstCooling` (reset time, else the rule's time, else 60 s; repeats double in `Fail`). Endpoint Gaps depend on Key State, so `invalid` reads "Mark invalid".
- **UI**: `pages/providers/RulesTry.tsx`: the `TryFailure` panel above the Flow view (Status, Endpoint when there are several, Body in a highlighted code field, Headers as `Name: value` lines, four examples, "Try this failure"; `sayResult` says which rule decided and shows the server's `key_effect` and `request_effect` as they come). Outcome colours and short names come from one map, `OUTCOME_KEY` (`lib/outcomes.ts`), shared with the Requests page's `attempt-info.ts`; the words of an effect are always the server's (`rules.KeyEffect`, `Outcome.RequestEffect`, `rules.Seconds` in Go, used by the rules list and classify alike). `CodeField` is a `<pre>` with `ui/highlight` under a transparent UI SDK `Textarea`; the pre sets the height and the frame scrolls both. `Rules.tsx` holds the result and clears it when the rules list changes; editing any input clears it too. `RulesFlow` takes `tried`; `traceOf(rules, tried)` marks each step `missed` ("Didn't match"), `match` (`aria-current="step"`, ring, lit branch, the engine's effect words) or `unreached` (dimmed), and the End card (`role=group` "No rule matched") when nothing matched, dimming the fallback line that didn't apply. ### Prompt caching 01: cache usage you can see
