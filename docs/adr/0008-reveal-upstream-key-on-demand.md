# Owner can reveal an Upstream Key value on demand

The Upstream Key value (`sk-…`) was originally set once, encrypted at rest with the installation master key, and never re-shown — the spec said "never shown again." The Owner had no way to copy a key out of Iroha once it was added, which made a forgotten key unrecoverable without a full re-add. We added a show-on-demand endpoint: `GET /api/v1/admin/providers/:id/keys/:keyId/value` decrypts the stored form, returns the plaintext to the Owner's authenticated session over the already-encrypted HTTPS channel, and records a `key.value.revealed` audit-log entry. The DB at rest stays encrypted; the plaintext exists only in the response and the Owner's browser session after they ask. The trust model shifts from "the server can never see the plaintext" to "the Owner can see it whenever they want, via a logged endpoint" — the same trust level the Owner already has over their own keys, with an audit trail to detect a stolen admin session. We rejected a "fingerprint" alternative (last 4 chars) because it doesn't let the Owner copy the key out, and we rejected making the encryption reversible by default because that breaks the at-rest guarantee against a stolen database copy.
