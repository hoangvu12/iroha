## Normalisers

Some Providers' answers are not quite their Shape: a model writes its reasoning into the text as `<think>…</think>`, GLM sends content as an array of blocks, MiniMax adds `audio_content` and a brand `name`, a stream ends without a `finish_reason`. Iroha rewrites these before the answer is passed through or translated, so OpenAI Chat Callers and Claude Code see the same clean answer (reasoning as `reasoning_content`, or as a thinking block on `/v1/messages`), whole or streamed. On the request side, a replayed message's `id` (Claude Code replays Anthropic message ids) never reaches an OpenAI Chat Endpoint; strict Providers such as Mistral refuse it with 422.

Normalisers are built in and need no configuration. `GET /api/providers/<handle>/summary` lists the ones that apply to the Provider under `normalisers` (name, `side`, `shape`, `host` when limited to one service, description, and the `endpoints` they apply to). Which apply follows from each Endpoint's Shape (today all are for OpenAI Chat Endpoints) and, for one service's own vocabulary, its host (`zai-finish-reasons` on `z.ai` and `bigmodel.cn`). Model quirks apply on every host, since relays and self-hosted servers pass them on; each acts only when the quirk is present, and an answer needing nothing is passed on byte for byte.

- A `<think>` block is lifted only when it opens the answer; a tag later in the text is the model's own words. An answer that already has `reasoning_content` is left alone.
- A Chat stream the Provider ends cleanly (`[DONE]`, or the end of its body) without a `finish_reason` gets a closing chunk (`stop`, or `tool_calls` after tool calls) and `[DONE]`. A stream that breaks off still ends with `upstream_stream_broken`.
- Z.ai's `finish_reason` `sensitive` becomes `content_filter` and `model_context_window_exceeded` becomes `length`. `network_error` means the answer failed: in a whole answer the Attempt fails (status 200, read as a 502 by the Failure Rules, so the next candidate is tried); in a stream that has begun it ends with `upstream_stream_error`.
