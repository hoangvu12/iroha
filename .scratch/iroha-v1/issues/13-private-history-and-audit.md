# 13 — Private request history and Owner audit

**What to build:** The Owner can diagnose inference and configuration behavior from metadata and audit trails without Iroha retaining inference content or secrets.

**Blocked by:** 02 — Secure single-Owner lifecycle; 05 — Single-key Chat Completions path.

**Status:** done

- [x] Request history records request ID, time, connection, exact model, selected key identity, status, latency, retry/skip trail, and provider-supplied token usage.
- [x] Prompts, responses, Upstream Key values, Gateway Key secrets, authentication headers, and unsafe upstream messages are never stored.
- [x] The Owner can filter, paginate, and inspect request metadata and individual retry decisions in the UI.
- [x] Owner mutations create audit records that identify the action and affected domain identity without secret before/after values.
- [x] Audit history remains until explicitly cleared.
- [x] Request-history retention is configurable, supports disabled storage, and defaults to 30 days.
- [x] Caller-safe errors contain a request ID but no internal key names or retry trail.
- [x] Systematic tests seed secret-like values through every error/log/audit path and prove redaction.

### Decisions worth knowing about

- **Lazy event writes.** The attempt rows have a foreign key to `request_events.id`, but the connection can be archived or purged between authorization and the first attempt. The service writes the event row on the first `startAttempt` (or directly in `recordSkip`), so a missing parent never aborts inference. `finalize` upserts the same row with terminal values, and every `recordAttempt` call sits inside a try/catch so a vanished connection becomes "no history row" rather than a 500.
- **Key identity vs. secret material.** The Owner's request-history view shows `keyId` (the public row identity) and never the encrypted or decrypted Upstream Key. The token-usage block is parsed from `usage.prompt_tokens` / `usage.completion_tokens` / `usage.total_tokens` only; nothing else in the upstream body is read.
- **Retention is cached.** The service caches the configured days value so every inference call does not pay an extra `settings.get`. `writeRetention` updates the cache, so an Owner toggle takes effect on the next request without restarting Iroha. The cache invalidation is `await this.#readRetentionSetting()` on first use after the process boots.
- **Disabled retention is a no-op recorder.** When the Owner sets `days: 0`, `beginRequest` returns a recorder whose `startAttempt` and `finalize` resolve immediately without touching the database. Inference keeps working; the Owner sees no rows.
- **Error paths are caller-safe.** The inference error envelope already carries the request ID; the ticket's assertion is that it does not also carry retry-trail or key-identity strings. The new `redaction.test.ts` proves the absence by seeding a known `Bearer` value into an `X-Echo` header that the upstream echoes in its error body.
- **Audit clearing is itself audited.** `DELETE /api/v1/admin/audit` records `audit.cleared` with the removed count. The next `GET /api/v1/admin/audit` returns exactly one row.
- **Provider Templates are not audited.** Connection duplication and the template-knowledge sync were already audited; Provider Templates themselves are data and need no separate action.

### Review

`/code-review` was run on the branch and its findings were applied before commit:
- The dead `eventWritten` short-circuit was kept only in `recordSkip`, because `startAttempt` may run more than once per request but `recordSkip` is mutually exclusive with attempts.
- The SQLite `recordAttempt` path no longer risks an FK violation: `recordSkip` writes the event before the attempt.
- The `Bearer`-prefix regex now preserves the scheme label so a log can still say "Bearer [REDACTED]".
- Settings retention cache is updated on `writeRetention` so the next call observes the change without a process restart.
- The PostgreSQL `audit` filter uses `ilike` so the action-prefix match is case-insensitive; SQLite uses `like` (already case-insensitive by default).
