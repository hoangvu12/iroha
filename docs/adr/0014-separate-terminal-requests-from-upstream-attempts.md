# Terminal Requests and upstream Attempts are separate observability facts

A Request records the completed response the Gateway delivered to its caller, while each Attempt records one Provider transmission inside that Request. Internal Request rows may exist while Attempts are running, but Owner history and analytics expose completed Requests only; a recovered `401 -> 200` Request is therefore successful and retains both Attempts plus a recovery indicator. We rejected treating the latest Attempt as the Request because locally generated responses, cancellation, streaming failure, and future hedging can make the caller-visible result differ from any one upstream Attempt, and rejected buffering all persistence until completion because a process failure would erase the retry trail.
