## Model metadata

Callers' model lists (`GET /providers/<handle>/v1/models`) carry what is known of each model, so clients such as Pi and OpenCode configure themselves: `context_length`, `max_input_tokens`, `max_output_tokens`, `architecture.input_modalities` / `output_modalities`, `reasoning`, `reasoning_levels` (each absent when unknown), and `chat`: `"ok"` unless the model is known not to chat (embedding, speech or image models). Metadata never decides whether a model is listed or routed.

Each field comes from the first source that knows it:

1. **Your overrides**: `POST /api/providers/acme/models {"model": "glm-4.6", "metadata": {"context_length": 1000000, "chat": "ok"}}`. `metadata` replaces all your overrides of that model; `{}` removes them. To change some and keep the rest, send `metadata_patch` instead: `{"model": "glm-4.6", "metadata_patch": {"context_length": 200000, "chat": null}}` sets one, removes one (`null`) and leaves the others as they are; use it in `POST .../models/bulk` to edit one field on many models. Same fields as the Callers' list. Audited and revertible like adding or hiding (resource `model`). An override keeps the entry even when discovery no longer finds it (it stays unlisted until found or added).
2. **The Provider's own list**, as discovery last read it: common field names are understood (`context_length`, `context_window`, `n_ctx`, `max_completion_tokens`, `inputTokenLimit`, OpenRouter's `top_provider` and `architecture`, numeric strings...).
3. **models.dev**, looked up after every refresh (also when discovery is `none`) and right after you add or override a model. Set the Provider's `models_dev_brand` to the models.dev provider ID its models are listed under (`PATCH /api/providers/acme {"models_dev_brand": "zai-coding-plan"}`; e.g. `anthropic`, `openai`, `alibaba-cn`, `minimax`, `openrouter`), then run a refresh: facts looked up under another brand are not used. Without a brand, models are looked up by name in models.dev's maker catalog only. Matching is exact (case ignored), a dotted version against a dashed one (`claude-opus-4.7` = `claude-opus-4-7`), or a bare name with exactly one numbered release (`muse-wonder` = `muse-wonder-1.0`); never a similar name. When several entries disagree, nothing is taken.

`GET /api/providers/acme/models` shows, per entry, `metadata` (what Callers see) and each source: `overrides`, `reported`, `models_dev`. A refresh answers `models_dev`: `ok`, `stale` (models.dev unreachable; its last catalog was used), `unavailable` (never read since start; earlier lookups kept) or `off`. A models.dev outage never fails a refresh; read why in `GET /api/logs?kind=models_dev`.
