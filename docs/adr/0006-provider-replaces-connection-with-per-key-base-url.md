# Provider absorbs Provider Connection; Upstream Keys may declare their own base URL

We renamed Provider Connection to Provider and lifted its single-base-URL constraint: a Provider now holds Upstream Keys whose base URLs may differ. The Owner creates one Provider on the providers page, sets a default base URL, and adds Upstream Keys that each may declare its own base URL; when unset, the key uses the Provider's base URL. Round-robin then naturally spreads across endpoints while the application still sees one Provider URL. We rejected adding a Provider entity above Connection (extra layer that does not solve round-robin), Endpoint as a first-class child of Connection (heavier model change for the same benefit), and opencode's per-Provider baseURL with one credential (forces one Provider per endpoint, which is the inconvenience the user reported). Transport, authentication, retry, timeout, capability, and idempotency settings stay Provider-scoped; only `baseUrl` is per-key. Gateway Key scope targets Provider IDs in place of Connection IDs. The discovery probe runs against the Provider's base URL and all keys share the model catalog.
