# Anthropic Inference Adapter owns the OpenAI ↔ Anthropic round-trip

A new typed `AnthropicInferenceAdapter` at `src/inference/anthropic-adapter.ts` is the single source of truth for Anthropic-specific behavior. It implements the existing `InferenceAdapter` contract (`src/inference/adapter.ts:87-91`) and owns the entire bidirectional translation between OpenAI-shape and Anthropic-shape: header construction (`x-api-key` or `Authorization: Bearer`, `anthropic-version` from the caller with a `2023-06-01` fallback, `anthropic-beta` join, `content-type`, `accept`); request transform (`system` hoisting, `max_tokens` defaulting via `getMaxTokensForModel` with a 4096 fallback, `tool_choice` mapping, tool-name sanitisation with a per-request forward/reverse map, `parallel_tool_calls` inversion); response transform (usage field translation, stop-reason mapping, error envelope mapping); streaming transform (Anthropic named SSE events → OpenAI chunk shape with per-stream state and usage accumulation); and the inverse direction for `/v1/messages` against OpenAI-shaped Targets. We rejected a separate translator module (duplicates streaming and tool-translation logic across modules and is paid for only by hypothetical second Anthropic-targeting adapters that are not on the roadmap), extending the Inference Adapter contract with `forwardOpenAiRequest` / `forwardAnthropicRequest` entry points (every future adapter would have to declare which caller shapes it accepts), and reusing the generic adapter (it cannot speak Anthropic — `system` hoisting, `x-api-key`, named SSE events, `cache_control`, `thinking`, `output_config`, and `tool_use_id` vs `tool_call_id` reconciliation are all Anthropic-specific). LiteLLM (`litellm/llms/anthropic/chat/transformation.py`), Portkey (`src/providers/anthropic/chatComplete.ts`), and Bifrost (`core/providers/anthropic/anthropic.go`) all put bidirectional translation in the typed adapter; the production evidence is consistent.
